Process

How it works, step by step

A clear pipeline from user input to actionable intelligence—no guesswork.

  1. 1

    Submit a URL

    Users enter any URL or hostname from the live scanner. The frontend sends a JSON payload to the BrandShield API over HTTPS-ready infrastructure.

  2. 2

    Backend validates & orchestrates

    Spring Boot authenticates the request shape, associates optional user context, and forwards a normalized analysis job to the AI microservice.

  3. 3

    AI service analyzes

    The Python engine evaluates TLS usage, length and complexity signals, and linguistic triggers—aggregating evidence into a score and verdict.

  4. 4

    Results persist & display

    SAFE or FAKE, score, and enumerated reasons return through the API, render in the UI, and save to history for logged-in accounts.

Under the hood

What our AI is actually measuring

BrandShield AI is designed to be transparent: you always see which factors influenced the outcome. The system prioritizes interpretability so security teams can train staff and tune policies.

  • Transport security — Non-HTTPS entry points are flagged because encryption is a baseline expectation for legitimate services.
  • Structural signals — Unusually long or noisy URLs can correlate with automated campaigns and cloaked redirects.
  • Language cues — High-risk terms often appear in phishing lures; we surface matches without claiming certainty on any single word.
  • Thresholded verdict — Evidence is summed into a capped score; crossing the policy threshold yields FAKE, otherwise SAFE—documented in every response.
